# 16. Единый экран модерации: все сцены, но только доказательные фрагменты

## Что изменилось после систематизации

Первая версия экрана показывала все 146 сцен, но для 84 из них подставляла детерминированный «черновик» — конкретную, но случайную минуту. Это удобно как кнопка, но неправильно по смыслу: «признание в любви» могло открыть любую сцену, а «женская дружба» вообще не была категорией.

Теперь экран работает по правилам [17-intent-taxonomy.md](17-intent-taxonomy.md):

- **все 146 сцен** остаются в одном списке;
- у каждой есть **основной интент** (14 категорий) и **ожидаемый тип фрагмента**;
- **таймкод появляется только у сцен, где SRT-окно прошло gate** под эту пару;
- у остальных статус **«нужен куратор»**, конкретный якорь эпизода и **никакого случайного времени**;
- `verified=1` ставится только оператором через «✓ Подтвердить».

## Экран

`http://localhost:8000/app/#/admin` → верхний блок **«🎬 Модерация таймкодов — 146 сцен»**.

Шапка показывает честные счётчики:

| Счётчик | Смысл |
|---|---|
| `✅ … сцен с доказательным фрагментом` | прошли gate, им есть что смотреть |
| `📌 … «нет таймкода — куратор»` | без времени, но с якорем, ссылками и формой добавления минуты |
| `▶ … с автозапуском` | официальный YouTube с `&t=<секунда>s` |
| `🔗 … ссылок на фильм` | ссылки есть у всех 146 сцен, даже без таймкода |
| `⏱ … с командой mpv` | `mpv --start=<время>` уже подставлен |
| `проверено …` | реальные `verified=1`, сейчас 0 |

Фильтры: **Все 146 / ▶ С таймкодом / 📌 Без таймкода / ✅ Проверенные** + поиск по названию + **фильтр по 14 категориям**.

Карточка с кандидатом содержит:

- чип категории («Признание в любви», «Женская дружба / сестринство», …);
- тип фрагмента (`монолог`, `диалог`, `песня`, …);
- отрезок `0:32:56–0:33:21`;
- **причину**: «3 смысловых совпадения, монолог, 32 сек, TF-IDF 0.42, консенсус 2»;
- якорь эпизода;
- «▶ Открыть на 0:32:56» / «⏱ Локально (mpv)» / «📌 Копировать якорь»;
- поля начала/конца, **обязательную версию издания**, метку момента и «✓ Подтвердить».

Карточка без кандидата показывает `ТАЙМКОД: — нет таймкода`, категорию, **якорь эпизода**, **ссылки на фильм** и форму «➕ Добавить таймкод в отсмотр». Кнопки «Открыть на моменте» и «✓ Подтвердить» появляются только после того, как куратор впишет конкретную минуту. Подробный сценарий — [18-curator-workflow.md](18-curator-workflow.md).

## Endpoint'ы

| Метод | Что делает |
|---|---|
| `GET /api/admin/moderation` | `items` на все 146 сцен + `stats` + `categories` |
| `POST /api/admin/moderation/curate` | куратор вписал минуту под якорь; создаёт `pending`, НЕ `verified` |
| `POST /api/admin/moderation/confirm` | `confirm` / `reject` / `skip`; только `confirm` ставит `verified=1`, обязателен `version_note` |
| `GET /api/admin/timecode-library` | старая служебная сводка |
| `POST /api/admin/timecodes/manual` | кураторский кандидат; теперь тоже получает `category` из разметки |

Старые служебные панели свёрнуты в `<details>«Служебные панели и старые очереди»</details>`.

## Покрытие в живой песочнице

```
сцен: 146
с таймкодом / к отсмотру: 44
кандидатов выше порога: 101
без таймкода, ждёт куратора: 102
ссылок на фильм: 146
проверено вручную: 0
```

62 сцены имеют SRT в кэше, но gate прошли 44: для остальных 18 совпадений с категорией оказалось меньше двух или скор ниже `0.45`. Это сделано специально — «на проверку уже попадали хорошие фрагменты», а не всё подряд.

Для 102 сцен без таймкода в карточке уже есть якорь и ссылки: куратор открывает фильм, находит этот эпизод, вписывает минуту и жмёт «➕ Добавить таймкод в отсмотр». Карточка сразу получает deep link на момент. Ручной поиск «с нуля» не требуется. Пошагово: [18-curator-workflow.md](18-curator-workflow.md).
