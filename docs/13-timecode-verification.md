# 13. Пилотная сверка таймкодов вручную

Этот документ — рабочая инструкция для оператора, который **вручную** проверяет кандидаты таймкодов в легальном плеере. Автоматическая библиотека даёт только «подсказки по времени»; официальным таймкод (`verified=1`) становится только после нажатия «✓ Подтвердить» в админке.

**Сейчас основной экран — [docs/16-moderation-board.md](docs/16-moderation-board.md)**: все 146 сцен в одной очереди, но таймкод получают только прошедшие категорийный gate. Таксономия — [docs/17-intent-taxonomy.md](docs/17-intent-taxonomy.md). Ниже сохранена подробная справка по полям и старым панелям.

## Что уже сделано кодом

- `data/timecode_library/pilot_manifest.json` — 20 кураторских сцен, 38 точных ссылок на SRT-зеркала OpenSubtitles на GitHub. Для большинства фильмов взято **две независимые версии субтитров**, чтобы работал консенсус ±10 сек. Вызывается через `--pilot`.
- `data/timecode_library/full_manifest.json` — **по умолчанию**: 62 сцены / 105 SRT+CSV из 4 зеркал, построено `scripts/build_full_manifest.py` по `srt_index.json`. Сомнительные совпадения помечены `ambiguous/match_note`, 6 ложных исключено.
- `data/timecode_library/imdb_map_full.json` — **133 IMDb ID на 140 сцен каталога** (ключ `название|год`, чтобы не путать «Начало» 1970 и 2010). 7 ID оставлены пустыми — не выдумываем.
- `scripts/import_timecode_library.py` — скачивает SRT/CSV в gitignored-кэш, конвертирует subtext-CSV во временный SRT, зовёт `scripts/fetch_timecodes.py` и складывает кандидатов в `timecode_candidates` со `status='pending'`. По умолчанию ограничивает 3 кандидата на сцену (`--max-per-scene`).
- `scripts/import_opus_timecodes.py` — отдельный адаптер OPUS / OpenSubtitles v2024 для Mac (корпус недоступен из песочницы). Подробнее: [docs/14-timecode-library-scale.md](docs/14-timecode-library-scale.md).
- В БД добавлены `scenes.imdb_id` / `scenes.tmdb_id`; старые заглушки `"0:00:00"` без `timecode_seconds` больше не считаются таймкодом и не показываются как `0:00:00`.
- Админка `#/admin` показывает описание момента нашими словами, предлагаемый отрезок, источник, лицензию, `confidence/consensus`, кнопку поиска фильма в плеере, копирование времени и поля для ручного уточнения перед подтверждением.

**Важно:** текст реплик из субтитров нигде не сохраняется. В БД остаются только `start/end`, `sha1` совпавшей строки, `source`, `source_license`, `confidence`, `consensus`, `auto` и наша `moment_label`.

## 1. Подготовка на локальном Mac

```bash
cd /Users/zlata/Desktop/timecod
printf 'PUBLIC_URL=http://localhost:8000\nADMIN_TOKEN=local-admin\n' > .env
.venv/bin/python scripts/import_timecode_library.py          # полный манифест
.venv/bin/python scripts/import_timecode_library.py --pilot  # только 20 кураторских сцен
bash scripts/dev.sh
```

`import_timecode_library.py` при первом запуске скачает ~105 SRT/CSV в `data/timecode_library/cache/` (папка в `.gitignore`). Основной канал — `raw.githubusercontent.com`, который **не расходует лимит GitHub REST API**; если raw-хост закрыт, скрипт сам уходит в `api.github.com`. Повторный запуск использует кэш; `--refresh` перекачивает заново. Если всё равно получил `403 rate limit exceeded`, задай `GITHUB_TOKEN`/`GH_TOKEN` в терминале:

```bash
export GITHUB_TOKEN=$(gh auth token)   # если GitHub CLI залогинен
.venv/bin/python scripts/import_timecode_library.py
```

CSV из `jblinder/subtext` автоматически превращаются во временный SRT.

Проверить, не записывая в БД:

```bash
.venv/bin/python scripts/import_timecode_library.py --dry-run --max-per-scene 2
```

После импорта в выводе будет число кандидатов и `pending`. **`verified=1` при импорте не ставится ни у одной сцены.** Полный прогон на чистой БД дал **186 pending-кандидатов для 62 сцен** (с `--max-per-scene 2` — 124); 133 сцены получили IMDb ID.

## 2. Что делать в админке

1. Открой `http://localhost:8000/app/#/admin`.
2. В поле «Admin token» введи `local-admin`, нажми «Сохранить», затем «Загрузить» (`#adm-load`).
3. Блок **«📥 Таймкоды из библиотек субтитров»** содержит очередь `pending`.
4. Для каждого кандидата:
   - прочитай «Наш момент» — это наше описание, а не реплика из фильма;
   - если есть кнопка **«▶ youtube_mosfilm · 0:47:12»** — нажми её: официальная бесплатная полная версия откроется **сразу на моменте** через `&t=<секунда>` (подробнее [docs/15-moderation-links.md](docs/15-moderation-links.md));
   - иначе нажми **«⏱ Локально (mpv)»** — скопируется команда с `--start`, подставь путь к своей легальной копии фильма; или **«🔍 Найти фильм в плеере»** / **«⏱ Копировать время»**;
   - открой фильм в легальном плеере, найди нужное издание и перемотай на предложенный отрезок;
   - если момент сместился — поправь поля **«начало»** и **«конец»** прямо в карточке;
   - укажи **«версия издания»** (например, «театральная, Kinopoisk 2024») — поле обязательное: без него «✓ Подтвердить» не отправит запрос, а бэкенд вернёт 400;
   - если плеер даёт прямую ссылку с позицией — вставь её в **«watch_url»**; если нет, оставь пустым: кнопки поиска останутся как fallback;
   - при необходимости уточни **«метку момента НАШИМИ словами»**;
   - нажми **«✓ Подтвердить»**. Только теперь у сцены появятся `timecode_label/seconds`, `timecode_end_label/seconds`, `verified=1`, `version_note` и выбранный `service`.
5. Если кандидат не подходит — **«✗ Отклонить»**: он уйдёт из очереди, сцена останется непроверенной.
6. Для фильмов, где SRT-зеркала ничего не нашли, используй панель **«🎬 Легальные полные версии для ручного поиска момента»**: открой официальную бесплатную версию, найди момент сам, впиши начало/конец/версию и нажми «＋ Добавить момент». Кандидат появится в общей `pending`-очереди. Алгоритм: [docs/15-moderation-links.md](docs/15-moderation-links.md).

Кнопка **«⚡ Авто-одобрение отключено»** заблокирована, а `POST /api/admin/timecodes/bulk-approve` по умолчанию возвращает 403. Авто-консенсус больше не может поставить `verified=1` без тебя; включить его можно только явным `ALLOW_BULK_AUTO_APPROVE=1` для экспериментов.

## 3. Как проверить результат

```bash
curl -s http://localhost:8000/api/scenes/meta
```

Ожидаемо: `total: 146`, `verified` растёт по мере подтверждений, `with_timecode` теперь считает только реальные `timecode_seconds`, а не заглушки.

Список ожидающих и сводка покрытия библиотеки:

```bash
curl -s -H 'X-Admin-Token: local-admin' \
  'http://localhost:8000/api/admin/timecodes?status=pending'
curl -s -H 'X-Admin-Token: local-admin' \
  'http://localhost:8000/api/admin/timecode-library'
```

Панель «📚 Библиотека таймкодов» в админке показывает те же цифры: сцены, IMDb ID, `pending/approved/rejected`, размер манифестов и реестр источников.

Одобренные моменты сцены:

```bash
curl -s http://localhost:8000/api/scenes/11/moments
```

Создай подарок с этой сценой — на открытке появится отрезок `0:50:19–0:50:56` вместо `—`, а кнопки плееров будут вести на выбранный сервис.

## 5. Юридические ограничения

- Мы не хостим видео, аудио фильма и текст субтитров.
- Таймкод привязан к **версии издания**: у театральной, режиссёрской и стриминговой версии время может отличаться. Поэтому `version_note` обязателен при ручной сверке.
- Источник и лицензия сохраняются в каждой записи кандидата; карточка источника в `docs/06-timecode-sources.md`.
- Перед коммерческим пилотом нужна отдельная юридическая проверка: `ODC-BY` у OPUS не отменяет прав правообладателей на тексты субтитров, а многие HF-датасеты имеют `CC BY-NC-SA` (только некоммерческое использование).
