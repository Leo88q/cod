# Дизайн: выбор букета через агентский договор с Flowwow

Дата: 2026-11-03. Цель: даритель выбирает букет прямо со страницы подарка «Сцены», заказ уходит на Flowwow, а комиссию нам платит **цветочный магазин** по агентскому договору (10–15%), а не площадка.

## 1. Модель и почему она выгодная

Flowwow — маркетплейс локальных студий (16 000+ магазинов, 1 200+ городов). Комиссии площадки с магазина: 5–23% за продажу (цветы в Москве ~20–23%) + ~3% эквайринг + 3% кэшбэк клиенту. **НО**: заказы, пришедшие по *прямой ссылке магазина*, идут с нулевой комиссией за продажу (только ~3% эквайринг) — это задокументированная программа Flowwow (подтверждена в публичных материалах 2021 и février 2026).

Значит, если мы приводим клиента на страницу магазина «снаружи» и это засчитывается как трафик магазина, площадка не берёт ничего, а магазин платит **нам** агентское вознаграждение. Это и есть наша «золотая жила»: мы не торгуем цветами, мы — канал.

**Важно**: засчитает ли Flowwow переход со *стороннего* сайта по ссылке магазина как «прямую ссылку» — вопрос №1 к ним в письменном виде (список вопросов в §6). От ответа зависит сценарий A или B.

## 2. Сценарии (выбираем по ответу Flowwow)

| Сценарий | Механика | Экономика для студии | Наша комиссия |
|---|---|---|---|
| **A. Zero-commission direct link (цель)** | наш ref в URL прямой ссылки магазина на Flowwow; заказ засчитывается магазину без комиссии площадки | экономит 20–23% площадке | 10–15% платит нам по агентскому договору |
| **B. Обычный заказ площадки** | ссылка flowwow.com с utm, заказ идёт как marketplace-заказ | площадка берёт 20–29% | либо студия платит нам из маржи, либо мы участвуем в партнёрке Flowwow (если примут) |
| **C. Fallback: свой checkout студии** | мы показываем букет и цену, заказ оформляется на сайте студии (или в нашем приложении с оплатой нам), дальше студия сама выполняет/через Flowwow | студия контролирует маржу | 10–15% нам |

Стартуем с A, страхуемся C. B — только если Flowwow подтвердит официальную агентскую программу с выплатами нам.

## 3. Сквозная механика (user flow + data flow)

1. Даритель на странице подарка нажимает «🌷 Добавить букет» → открывается `#/bouquets?g=<код>` с городом получателя (авто из подарка, можно сменить).
2. `GET /api/bouquets?city=...` → карточки букетов (название, цена, фото, студия) из нашего кэша витрины.
3. Выбор букета → модалка «Оформить на Flowwow · N ₽» → `POST /api/gifts/{id}/order-bouquet {bouquet_id, amount}` → создаётся запись `orders` со статусом `pending` и нашим `ref_code = scena_<gift>_<rand>`; ответ — ссылка агрегатора с `utm_source=scena&utm_medium=gift_page&utm_campaign=gift_<id>&ref=<ref>`.
4. Клик → `GET /api/orders/{id}/go` → фиксируем `clicked_at`, статус `clicked`, редирект 307 на Flowwow (в боте — `openTelegramLink`, в вебе — новая вкладка).
5. На Flowwow заказчик вводит телефон/адрес получателя и оплачивает (мы эти данные **не видим и не храним** — хорошо для 152-ФЗ).
6. Магазин видит заказ в своём кабинете Flowwow (вопрос №4: видит ли он наш ref/utm в заказе — если да, атрибуция автоматическая).
7. Подтверждение заказа и начисление комиссии:
   - **ручной контур (старт)**: магазин в нашем кабинете вводит id заказа Flowwow + сумму → `POST /api/shops/{id}/orders/confirm {flowwow_order_id, amount}` → заказ `confirmed`, комиссия фиксируется (реализовано сейчас);
   - **авто (цель)**: webhook/API Flowwow для партнёров (вопрос №2) либо seller API — тогда статусы подтягиваем сами.
8. Выплаты: раз в неделю/две — реестр по ref → акт → оплата на расчётный счёт ИП (УСН 6%). Комиссия считается от суммы заказа без доставки (обсудить).

## 4. Атрибуция и антифрод

- Один заказ = один ref; дубликаты по ref не оплачиваются.
- Сверка: id заказа Flowwow + сумма у магазина должны совпасть с нашим реестром; расхождения — спор в течение 14 дней (chargeback/возвраты не оплачиваем).
- Запрещено: саморефералы, накрутка, заказы «для себя», оплата бонусами площадки с целью накрутки. В договоре — пункт об ответственности и штрафе (100–150% комиссии, как у самой Flowwow к магазинам).
- Ref не содержит ПДн; телефон получателя вводится на стороне Flowwow и нам не передаётся.

## 5. Агентский договор: ключевые пункты (шаблон для юриста)

1. Предмет: Агент (мы, ИП) привлекает покупателей на сайт/приложение Flowwow и страницы магазинов-партнёров по ссылкам с ref/utm; Принципал (магазин) выплачивает агентское вознаграждение.
2. Вознаграждение: 10–15% от стоимости заказа (без доставки/упаковки), НДС включительно/нет — по УСН 6% без НДС, но прописать.
3. Порядок расчётов: реестр заказов по ref за период → акт → оплата в течение 5–10 банковских дней. Удержание при возвратах.
4. Отчётность: агент предоставляет реестр (дата, ref, id заказа Flowwow, сумма, статус).
5. Техническая часть: формат ref, utm-параметры, отсутствие подмены ссылки, запрет на кэшбэк-манипуляции.
6. ПДн: стороны не передают друг другу ПДн клиентов; заказчик вводит данные непосредственно у Принципала/площадки.
7. Реклама (ФЗ-38): если будем размещать рекламу Flowwow/магазинов — маркировка «Реклама» + ЕРИР. В приложении — не реклама, а переход по выбору пользователя.
8. Срок и расторжение, штрафы за накрутку, применимое право (РФ), претензионный порядок.

## 6. Вопросы Flowwow (письмо на partners@flowwow.ru / partner@flowwow.com)

1. Засчитывается ли переход по ссылке со стороннего сайта (наш ref/utm на странице магазина) как «прямая ссылка магазина» с нулевой комиссией за продажу? Письменное подтверждение, пожалуйста.
2. Есть ли официальная агентская/партнёрская программа для агрегаторов: API или webhook статусов и сумм заказов, выплаты агенту?
3. Можем ли мы получить seller API-доступ как агент (не продавец) — для сверки заказов?
4. Видит ли продавец в заказе utm/ref параметры перехода?
5. Есть ли deeplink форматы приложения Flowwow (товар/корзина/магазин) для открытия «в один клик»?
6. Условия B2B-сегмента «Подарки для бизнеса» (info.flowwow.com/corporate): можно ли нам как партнёру приводить корпоративных клиентов и на каких условиях?
7. Какой юридический документ регулирует zero-commission программу (ссылка на оферту/публичные условия)?

## 7. Что уже в коде и что допиливаем

Уже есть: витрина букетов (`/api/bouquets`), создание заказа с ref (`POST /api/gifts/{id}/order-bouquet`), клик-фиксация и редирект (`/api/orders/{id}/go`), таблица `orders` со статусами и комиссией, статистика студии.

Допиливаем в этом раунде: город получателя в подарке (автофильтр букетов), подтверждение заказа магазином из кабинета (`POST /api/shops/{id}/orders/confirm` + список заказов), кнопка «ответить подарком» после ответа (виральная петля).

## 8. Экономика на примерах

- Букет 3 490 ₽ → наша комиссия 10% = **349 ₽** с одного заказа.
- 5 пилотных студий × 20 заказов/мес × 349 ₽ ≈ **35 тыс ₽/мес** + карточки (5 × 30 карт × 50 ₽ = 7,5 тыс) + подписки (5 × 990 = 5 тыс) ≈ **~47 тыс ₽/мес** с 5 студий.
- Масштаб: 100 студий × 20 зак./мес = 2 000 заказов × ~350 ₽ ≈ **700 тыс ₽/мес** комиссии + B2B-подписки ~100 тыс. Это и есть «золотая жила» — при условии, что сценарий A (zero-commission) подтвердится письменно.

## 9. Риски

| Риск | Митигация |
|---|---|
| Flowwow не засчитает внешний трафик как direct link | сценарий C (свой checkout студии) / партнёрка Flowwow; вопрос №1 в первую очередь |
| Магазин не подтверждает заказы | авто-атрибуция по ref у продавца (вопрос №4) или webhook; ручной контур как fallback |
| Споры по атрибуции | реестр по ref, сверка по id заказа, 14-дневное окно |
| Зависимость от одной площадки | параллельно FloMarket, Florist.ru, Grand Flora, прямые студии |
| Юриск агентства | договор с юристом, реестр, акты, маркировка рекламы при необходимости |
