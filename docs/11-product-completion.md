# Продолжение реализации: согласия, владельцы, удаление и безопасные загрузки

Дата: 04.11.2026. При расхождении со старыми аудитами документы 11 и 10 описывают актуальный код.

## Реализовано и проверено

### Взаимное подтверждение связи

- `POST /api/connections` создаёт pending-запрос. Самосвязь запрещена.
- `GET /api/connections` показывает собственные входящие/исходящие запросы.
- `POST /api/connections/{id}/accept` доступен только получателю; повторное подтверждение безопасно.
- `DELETE /api/connections/{id}` доступен участнику для отказа/отзыва.
- Таймлайн показывает только accepted-связи. Даже принятие связи **не даёт доступ** к чужим private API.
- UI таймлайна позволяет принять, отклонить и разорвать связь.
- Старые односторонние связи мигрируют в pending без выдуманного согласия: одному из участников нужно повторно отправить запрос, второму — принять.

### Владельцы студий

- `shops.owner_user_id`; назначение/передача только оператором через `POST /api/admin/shops/{id}/owner {telegram_id}`. Владелец должен ранее войти в Mini App.
- `require_shop` проверяет подписанную Telegram-личность и принадлежность студии. Глобальный админ имеет доступ; чужой владелец — нет.
- Ограничены статистика, список/подтверждение заказов, создание B2B-платежей, просмотр платежа и покупка карточек.
- Бесплатный выпуск карточек остаётся **только у оператора**, не у владельца (иначе обход оплаты).
- `GET /api/shops/mine`; новый пункт навигации «Студия» и выбор назначенной студии. В админке — форма назначения владельца.
- Пока один владелец на студию. Команды сотрудников, granular roles, история передачи владения — не реализованы.

### Удаление профиля

- `POST /api/account/delete {confirmation:"УДАЛИТЬ"}` использует подписанную личность, а не чужой ID из тела запроса. В dev ALLOW_ANON заявленные ID остаются тестовым режимом.
- В production без авторизации — 401; неверное подтверждение — 400.
- Если есть студия во владении или pending-платёж — 409: требуется передать владение/разрешить платёж через поддержку.
- Одна транзакция очищает профиль, связи, даты, закладки, личные списки, уведомления, связанные согласия/жалобы/события, собственные ответы/заметки и содержимое подарков. Подарки становятся недоступными; пользовательские ссылки/подписанные медиа больше не дают доступ.
- Платёжные записи отвязываются от профиля, но сумма/статус/ID провайдера сохраняются для учёта. Публичные предложения сцен отвязываются от пользователя, но публичный контент не уничтожается автоматически.
- Непривязанные медиа очищаются шедулером, свежие файлы могут физически сохраняться до 48 часов. Резервные копии и данные внешних провайдеров не стираются этим API.
- Повторный вход из Telegram создаёт пустой профиль; прежние подарки не восстанавливаются.
- UI таймлайна содержит явное необратимое подтверждение. Это технический механизм, **не юридическое заключение** о полноте исполнения требований субъекта.

### Проверка содержимого upload

- Одного расширения больше недостаточно: файл должен реально декодироваться.
- Фото: Pillow, ограничение 20 млн пикселей, максимум стороны после обработки 2048, новый JPEG без EXIF/комментариев/профилей. Анимация GIF/WebP не сохраняется, прозрачность заменяется белым фоном.
- Аудио: bundled FFmpeg из `imageio-ffmpeg`, ввод/вывод через pipe, разрешён только протокол pipe (без сетевых и файловых ссылок), timeout 25 сек, audio-only MP3, mono/24 kHz/48 kbps, максимум 300 сек. Более длинная запись обрезается до 5 минут; клиент также останавливает запись через 5 минут.
- Исходник после обработки не публикуется и удаляется; ошибки обработки удаляют временные файлы.
- Не более двух нормализаций одновременно на процесс; перегрузка — 429/Retry-After. Отдельная квота upload 10/мин по умолчанию. Сигнатурный антивирус не добавлен; декодеры также требуют регулярных security updates.
- Production Caddy ограничивает всё тело запроса 12 MB, приложение — файл `MAX_UPLOAD_MB` (по умолчанию 10 MB). При изменении лимита согласовать обе настройки. В обход ingress multipart может начать разбор до проверки файла — не публиковать uvicorn наружу.
- Voice UI использует фактический MIME MediaRecorder (включая mp4/m4a), освобождает микрофон и object URL, прекращает запись при переходе и блокирует создание подарка до завершения обработки.

### Данные и ввод

- Новые согласия хранят `policy_version`; старые NULL-версии не подделываются задним числом.
- Privacy больше не утверждает неподтверждённое размещение сервера в РФ и не обещает автоматического удаления всех записей через 30 дней.
- `OPERATOR_NAME`, `OPERATOR_INN`, `OPERATOR_CONTACT`, `HOSTING_REGION` задаёт оператор; preflight требует их заполнения. Само заполнение не доказывает юридическое соответствие.
- Экспорт дополнен собственными студиями, предложенными сценами, списками и жалобами.
- Дата отложенного открытия требует ISO8601 с timezone, нормализуется в UTC. Проверяются существование календарной даты и диапазон remind_days, длина имени/число сцен.

## Проверки

- **64 Python-теста**, в том числе новые тесты взаимного согласия, изоляции владельцев, удаления профиля/внешних ключей, подменённого upload, удаления метаданных и реального транскодирования аудио.
- **6 DOM-тестов**, включая контролы согласия/удаления и выбор только назначенных студий.
- `node --check app/static/app.js` и общий `scripts/check.sh`.
- FFmpeg/Pillow реально установлены и отработали в песочнице; версии включены в `requirements.lock.txt`.

## Остаётся открытым

- Юридическая приёмка удаления/сроков/бэкапов; фактические реквизиты и договоры оператора.
- Возвраты, фискальные чеки, реальная платёжная/партнёрская приёмка.
- Аудит security декодеров/антивирус, квоты дискового пространства и обновление зависимостей.
- Многоуровневые роли студий, полный audit trail действий операторов.
- Browser E2E/визуальные регрессии/реальные iOS и Android, WCAG-аудит, пользовательский пилот.
- Реальные алерты, offsite backup, Docker-сборка и HTTPS/DNS на production-хосте: из этого окружения не подтверждены.
- Redis/горизонтальное масштабирование, CDN, полная дизайн-система, качество и права всего каталога.

Документ не закрывает эти пункты только по факту добавления нескольких API.
