# 22. Продукт без фильмов: что можно строить вместо кинотеки

Дата: 16.11.2026. Ответ на вопрос «как вообще не касаться фильмов».

## Почему это правильный вопрос

Фильмы тянут за собой четыре долга, которые никогда не заканчиваются:

1. **Права.** Нужна легальная копия в плеере; кадры/реплики нелья показывать.
2. **Издания.** Таймкод «плывёт» от версии к версии — нужен `version_note` и вечная
   сверка.
3. **Играбельность.** Момент есть, а включить негде: из 11 доказанных сцен
   ссылку на плеер имеет **0**.
4. **Плотность.** Один фильм = 1–2 момента, а подарков много.

Контент, который создаёт сам пользователь, не имеет ни одного из этих долгов.
Проверка: `ffmpeg` уже в зависимостях, сборка 3 фото + голос = **2.7 сек**,
MP4 1080×1920, 313 КБ (см. `scripts/make_film.py`, `tests/test_make_film.py`).

## Варианты (от самого дешёвого к самому смелому)

### A. «Ваше кино» — вертикальный фильм из фото и голоса ✅ реализовано

Пользователь дарит не чужой кадр, а **свой**: 3–10 фото, к каждому подпись,
сверху — голосовое. На выходе MP4, который получатель смотрит прямо в Telegram.

- **Юридически:** ноль чужих прав. Всё, что на экране, прислал сам пользователь.
- **Технически:** ffmpeg + Pillow, локально, без внешних API. `POST /api/film/build`
  принимает только пути из нашего `/api/upload`, отдаёт подписанную ссылку.
- **Продуктово:** это «наш общий фильм» буквально, а не метафора. И это шарится:
  человек покажет такой ролик в сторис, а подарок-ссылку — нет.
- **Ограничение:** нужны фото и 20 секунд смелости записать голос. Часть людей
  отвалится на этом шаге — лечится подсказками и готовыми подписями.

### B. «Фильм из ваших переписок» — кино о вас, собранное из вашего архива

Те же фото, но структура задаётся не пользователем, а поводом: «как мы
познакомились», «наши пять лет», «год, когда всё изменилось». Приложение
предлагает раскадровку, человек только подтверждает и вставляет фото.

- Почти без нового контента: раскадровки — наши тексты (это дёшево и полностью наше).
- Даёт «сценарий» — самую ценную часть: людям тяжело придумывать, что писать.
- Тот же движок, что в A. Можно делать за один вечер.

### C. «Письмо, которое дойдёт позже»

Отложенная открытка — механизм уже есть (`open_at`, серии на несколько дней).
Пользователь пишет 7 коротких сообщений, получатель читает по одному в день.
Контент — только текст, ноль медиа, ноль прав.

- Самое дешёвое в разработке, высокая эмоциональная отдача.
- Хуже шарится (это личное, не для сторис).

### D. Совместный альбом-«сценарий» — два участника, один фильм

Получатель не просто смотрит, а **добавляет свой кадр** — и ролик пересобирается
уже из двух наборов. Это то, чего нет у «подарка»: асимметрия снимается.

- Механика ответов в коде уже есть (`replies`, тип `scene/message`).
- Сильнейшее удержание: с каждым обменом фильм становится длиннее.
- Требует сборки «на лету» при каждом добавлении — дёшево, если кэшировать кадры.

### E. Кино без прав: общественное достояние

Если всё-таки хочется «кадры из настоящего кино», есть законный путь: фильмы в
общественном достоянии (США до 1929, часть советских без восстановленных прав,
«Носферату», «Метрополис», ранний Чаплин). Их можно показывать кадрами.

- Даёт визуал мирового кино без риска.
- Узкая эстетика (ч/б, немое) — не для всех поводов.

### F. Аудио-путь: подкаст-«сцена» вместо видео

Только голос + обложка + наши тексты. Ещё дешевле видео, работает при плохой сети.

## Что я реализовал сейчас

**Вариант A целиком, на уровне API и рендера:**

| Что | Где |
|---|---|
| Рендер кадров, подписи, градиент, прогресс-полоски, кириллица | `scripts/make_film.py` |
| Сборка MP4 1080×1920, кадры подстраиваются под длину голоса | там же (`build`) |
| Ограничения: 10 фото, 90 сек, таймаут ffmpeg, временные файлы удаляются | там же |
| API: `POST /api/film/build` с проверкой путей и авторизации | `app/main.py` |
| Лимит одновременных сборок (2 на процесс), подписанная ссылка | `app/make_film_service.py` |
| 12 тестов (рендер + API + защита от `../`) | `tests/test_make_film.py`, `tests/test_film_api.py` |

Кадр из прототипа: `docs/assets/your-film-frames.png`.

## Честные минусы A

- **Нет «магии узнавания»**. Сила кино — в том, что человек узнаёт сцену, которую
  любит. Своё видео этого не даёт. Поэтому A **не заменяет** сцены, а снимает
  зависимость продукта от них: подарок становится возможным без кинотеки.
- **Нужны фото.** Если фото нет — продукт пустой. Лечится режимом «только текст
  + голос» (вариант F).
- **Права на фото** остаются у пользователя: публиковать чужое лицо без согласия
  нельзя — нужен тот же чекбокс согласия, что уже есть в форме подарка.
- **CPU.** Сборка ~1 сек на кадр при `veryfast`; для потока нужна очередь и кэш.

## Рекомендация

**A + B + D** — это одна механика с разными обёртками:

1. **B** задаёт раскадровку (наши тексты — дёшево и уникально),
2. **A** рендерит фильм (уже готово),
3. **D** позволяет получателю дописать кадр, и фильм растёт.

Кинотека при этом остаётся **необязательным слоем**: если у сцены есть
`playable_url`, мы предлагаем «добавить кадр из фильма»; нет — продукт всё равно
работает. Именно это убирает риск «упёрлись в фильмы».

Открытые вопросы для решения:
- сколько фото минимум (сейчас 1, для «фильма» лучше 3);
- нужен ли фоновый трек (сейчас только голос);
- кто платит за CPU: включать в премиум 499 ₽/год или бесплатно с лимитом.
