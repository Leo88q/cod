# 24. Что делать с таймкодами: замена источника, а не отказ

Дата: 16.11.2026. Ответ на «возможно их нужно заменить вовсе, потому что мы не
можем автоматизировать легально».

## Короткий ответ

**Заменить — да. Отказаться — нет.** Убрать надо не таймкод, а **субтитры как
источник**. Время сцены можно получить из самого видео, которое мы вправе
показывать. Тогда:

- **8 из 14** наших официальных видео трогать не нужно вообще;
- для них таймкод считается **бесплатно и локально** — из картинки;
- юридический риск падает до нуля: субтитры не скачиваются и не читаются.

## Почему нынешняя схема не масштабируется (это не мнение, это цифры)

| Факт | Значение |
|---|---|
| Сцен в каталоге | 140 |
| Совпало с субтитрами | **61** (44%) |
| Итог движка доказательств | `auto` **11**, `review` 39, `none` 7, `published` 11 |
| Совпадений «сцена ↔ официальное видео» | **0 из 11** |
| Официальных видео с доказательствами | **0 из 14** |
| Лицензия источника | OpenSubtitles community через GitHub-зеркала |

То есть текущий конвейер даёт **0 легально показываемых сцен**. Он не «плохо
настроен» — он упирается в лицензию: субтитры это производное произведение,
массовая автоматическая обработка базы OpenSubtitles вне их API — нарушение, а
хранить текст мы и так запретили себе сами.

Добавь сюда исчезающий ресурс (зеркала уже сейчас живут на 4 GitHub-аккаунтах,
один из них удалённый) — и станет ясно: строить продукт на этом нельзя.

## Что проверено прямо сейчас (новое)

Написан и протестирован детектор монтажных склеек по картинке:
`scripts/detect_cuts.py` — 64×36 RGB, 10 к/с, numpy, без нейросетей.

| Проверка | Результат |
|---|---|
| Видео с известными границами 3 с / 6 с | найдено **3.2 и 6.2** — точность ±0.2 с |
| Статичный кадр 4 с | **0 склеек** (ложных нет) |
| Один кадр 3 с | **0 склеек** |
| Битый файл | **0 склеек**, без падения |

Отдельно важный урок: **порог нельзя делать абсолютным**. В статичном видео
медиана и MAD разницы кадров равны нулю, любой «порог 0.3» даёт мусор. Рабочий
критерий — пик в 8 раз выше медианы своей окрестности.

Стоимость: весь фильм в 64×36 на 10 к/с — это мегабайты и секунды CPU, а не
часы. Никакого распознавания речи, никаких внешних API.

## Три варианта источника таймкодов

### A. Склейки из нашего же видео — брать сейчас

- Работает на всём, что мы вправе показывать: официальные Rutube-каналы
  (Мосфильм), общественное достояние, «Ваше кино».
- Даёт **границы кадров**, а не «эмоциональные моменты». Момент = кадр между
  двумя склейками. Для нашей подачи это честно: мы и так показываем фрагмент.
- 0 ₽, 0 внешних зависимостей, работает офлайн.
- Минус: не различает «свадьбу» и «драку» — это работа нашей разметки чувств,
  а не таймкода.

### B. Купленная библиотека с правом показа — когда появится выручка

Любой легальный API кадров/таймкодов (или прямая лицензия у правообладателя)
даёт «момент + право показать». Тогда движок доказательств становится не нужен:
лицензия и есть доказательство. Дорого, но это единственная схема, которая
масштабируется на современное кино.

### C. Открытый корпус без прав — не наше будущее

Субтитры, скрейпинг каталогов, «а мы только таймкоды» — это то, от чего уходим.
Даже если технически работает, продукт с этим нельзя продавать студиям.

## Что предлагаю менять в продукте

1. **Поле сцены = пара (начало, конец), а не один момент.**
   Аргумент не юридический, а продуктовый: склейки дают интервалы, и подарок
   «с 12:04 по 12:31» ощущается куском фильма, а не вырванным кадром.
2. **Признак «чем цепляет» задаём мы, а не субтитры.**
   Сейчас `evidence_engine` выводит эмоцию из лексики (и это был обход правила
   «текст не хранить»). С детектором склеек лексика не нужна вовсе: размечаем
   сцены по времени и по тому, что видно, — и правило «не хранить текст»
   становится тривиальным.
3. **Право показа первично, доказательство вторично.**
   Сцена без `playable_url` не может быть подарком — это уже наш критерий.
   Значит и таймкод имеет смысл только для того видео, которое мы вправе
   показать. Порядок: *сначала видео с правами, потом таймкод к нему.*
4. **Движок доказательств не выбрасывать, а сузить.**
   Консенсус изданий остаётся полезным ровно для одного: проверить, что две
   версии видео — одно и то же издание. Это дешевле и легальнее, чем
   подтверждать эмоции.

## Что это значит для демо

Демо «чувство → 3 момента → ▶» **не зависит** от кинотеки и не ломается:
моменты берутся из «Вашего кино» (свои фото + голос) — там склейки известны
заранее, потому что мы сами их ставим.

Кинотека — необязательный слой. Если завтра она исчезнет целиком, продукт
останется на ногах.

## Итог

| Вопрос | Ответ |
|---|---|
| Заменить таймкоды? | **Нет.** Заменить **источник**: видео с правами вместо субтитров |
| Можно ли автоматизировать легально? | **Да**, для своего и официального видео — детектор склеек уже работает |
| Нужны ли субтитры? | **Нет.** Ни для склеек, ни для эмоций |
| Что делать с 61 сценой на субтитрах? | Оставить как есть, но **не** строить на них демо и не называть доказанными |
| Срочность | Не пожар: демо от кинотеки не зависит. Но и вкладывать в субтитры больше не надо |

Следующий шаг, если согласен: подключить `detect_cuts.cuts()` к сбору
библиотеки — для 8 официальных видео получить реальные интервалы сцен и
посмотреть, сколько из 140 сцен каталога закрывается без единого субтитра.
