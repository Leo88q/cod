# 23. Другие площадки и что взять с GitHub

Дата: 16.11.2026. Ответ на «как интегрироваться с другой соцсетью» и «поищи на GitHub».

## Короткий вывод

**Одно приложение — три площадки.** Регистрируемся в VK Mini Apps, и оно
автоматически работает в Одноклассниках: по документации ОК создание
приложений внутри ОК больше не поддерживается, всё идёт через VK Mini Apps, а
VK Bridge в ОК поддерживает `VKWebAppInit`, `VKWebAppShare`,
`VKWebAppShowWallPostBox` и не поддерживает только истории и «избранное».

То есть вторая соцсеть достаётся **бесплатно** — при условии, что авторизация не
прибита гвоздями к Telegram. Это уже сделано: `app/platform_auth.py`.

## Площадки: что реально доступно

| Площадка | Вход | Mini App | Ограничения для нас |
|---|---|---|---|
| **Telegram** | initData, HMAC | зрелые, есть SDK | базовый вариант, всё уже работает |
| **VK** | подписанные launch params (`sign`) | зрелые, `@vkontakte/vk-bridge` MIT, бесплатно | нужен «защищённый ключ» и проверка подписи на бэкенде |
| **ОК** | через VK | работают через VK Bridge | нет историй; аудитория 35+ — это как раз «мама/семья» |
| **MAX** | WebApp | ранняя стадия | **публиковать могут только верифицированные юрлица РФ** (ИП/ООО), нет deep links, нет истории |
| **WhatsApp / iMessage** | нет Mini Apps | — | только обычная ссылка |

### MAX — важный нюанс

Технически платформа похожа на Telegram (Bot API, вебхуки, WebApp, SDK для
Python/TS/Go, РФ-периметр для 152-ФЗ). Но с осени 2025 ботов и мини-приложения
публикуют **только верифицированные организации** (юрлицо РФ с приложением в
RuStore или регистрацией на МСП.РФ). Для продукта «два человека дарят друг другу
сцену» это блокер: регистрация юрлица ради MVP не нужна.

Вывод: MAX — второй-третий шаг, когда появится ООО ради карточек для студий.
Архитектурно мы к нему готовы: тот же WebApp + REST, меняется только слой
отправки сообщений.

## Что я реализовал

| Что | Где |
|---|---|
| Проверка подписи VK на бэкенде (base64url HMAC-SHA256, канон `vk_*` по алфавиту) | `app/platform_auth.py: validate_vk_launch` |
| Единая модель: `user_identities(provider, external_id) → users.id` | `db/schema.sql`, миграция в `app/db.py` |
| Telegram-совместимость сохранена: `users.telegram_id` не тронут | там же |
| `POST /api/auth/vk`, `GET /api/platform` | `app/main.py` |
| Клиентский мост для трёх платформ + нативная история VK для «вашего кино» | `app/static/platform.js` |
| 12 pytest на авторизацию, 2 UI-теста на мост | `tests/test_platform_auth.py`, `tests/ui` |

Проверено тестами: подменить `vk_user_id`, сохранив подпись, **нельзя**; чужой
секрет, протухший `vk_ts`, отрицательный или гигантский id отклоняются.

## Шеринг: где продукт растёт

- **VK/ОК** — `VKWebAppShowStoryBox` открывает нативный редактор историй:
  «ваше кино» уходит в сторис одним тапом. В ОК истории не поддерживаются —
  там `VKWebAppShare` и запись на стену.
- **Telegram** — `switchInlineQuery` и `t.me/share`.
- Веб — `navigator.share`.

Для «Сцены» это критично: подарок — интимная ссылка, её не пересылают. А ролик
из своих фото — пересылают. История в VK/ОК — самый дешёвый органический канал.

## Что взять с GitHub (и что не брать)

Искал по `stars:>20` через GitHub API. Итог:

### Берём

| Пакет | Лицензия | Зачем |
|---|---|---|
| `@vkontakte/vk-bridge` 3.0.2 | MIT | официальный мост VK/ОК, обязателен для Mini App |
| `@vkontakte/vkui` 8.5.1 | MIT | готовая дизайн-система VK: если делаем VK-версию, не изобретаем UI |
| `Telegram-Mini-Apps/reactjs-template` ★430 | MIT | эталон структуры TMA, если будем переписывать фронт на React |
| `aiovk` 4.1.0 / `vkbottle` 4.11.0 | MIT | Python-обёртки VK API: посты в сообщество, статистика, рассылки |
| `maxapi` 1.2.4 | MIT | Python-обёртка MAX Bot API (на будущее, когда будет юрлицо) |
| `imageio-ffmpeg` (уже в проекте) | BSD | сборка видео, работает и на сервере, и на Mac |

### Не берём

- **Готовые генераторы слайд-шоу и видео-конструкторы** — не берём: видео из
  продукта убрано (см. `docs/29-video-removed.md`), а ffmpeg остаётся только для
  служебных задач (обложки, чтение видео в детекторе склеек).
- **`vk-tunnel` 1.0.0** — разработка заброшена, лицензия не указана. Для локальной
  отладки VK Mini App лучше официальный `vk-miniapps-deploy` / ngrok.
- **`ok_api`** — не нужен, пока идём через VK Mini Apps.
- **VKUI «как есть»** без нужды: наша Mini App уже написана на ванильном JS,
  переезд на VKUI = переписать 1500 строк `app.js` ради нативного вида.

## Что это даёт продукту

1. **Вторая соцсеть бесплатно** — ОК через VK, аудитория 35+ (подарки маме/семье).
2. **Органический рост** — истории VK для роликов «ваше кино».
3. **РФ-периметр** — если позже понадобится MAX, код почти готов, но нужен юрлицо.

## Ограничения, которые надо помнить

- **Подпись проверяется только на бэкенде.** `sign` из URL — не доказательство.
  Это покрыто тестами; фронтенд никогда не решает, «кто я».
- **Связывание аккаунтов** (один человек в Telegram и VK) сейчас даёт две записи:
  автоматически сливать нельзя — можно склеить чужие истории. Нужен явный
  сценарий «войдите ещё раз в другом мессенджере и подтвердите связку».
- **ОК без историй**, MAX без Mini Apps для физлиц — не закладывать в MVP.
- **Публикация VK Mini App** проходит модерацию VK; для витрины ОК — отдельная
  проверка. Сроки в документации не фиксированы.
