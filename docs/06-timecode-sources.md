# 06. Откуда брать библиотеку таймкодов (и что с этим делать по закону)

**Наше правило (жёсткое):** пользователю показываем только факты — название, год, таймкод — плюс наше описание и ссылку на легальный плеер. Текст субтитров и дословные реплики **нигде не храним и не показываем**. Поэтому из библиотек субтитров мы извлекаем **только таймкоды** (факт), а каждую запись снабжаем `source` + `source_license`. Таймкод становится официальным (`verified=1`) только после ручной проверки в легальном плеере админом.

## Источники (проверено 2026-11-03)

| Источник | Что даёт | Лицензия / условия | Как используем |
|---|---|---|---|

## Что разрешено, а что нет (наша правовая позиция)

- ✅ Таймкод (время начала сцены) — **факт**, не охраняется авторским правом (ст. 1259 ГК РФ аналог: facts not protected). Название фильма и год — тоже факты.
- ✅ Наше собственное описание происходящего — наш объект авторского права.
- ❌ Дословные реплики и выдержки из субтитров — охраняемый текст; **не копируем, не храним, не показываем**. В БД храним только `sha1` совпавшей строки для перепроверки.
- ❌ Видео и обложки — не хостим; только ссылки на легальные плееры.
- ⚠️ Субтитры конкретного издания привязаны к **версии фильма** — поэтому у сцены храним `service` + `version_note` + `verified`: один и тот же таймкод может отличаться в разных изданиях (театральная/расширенная/TV).

## Пайплайн (реализован, автономный + анти-мусор)

1. `scripts/fetch_timecodes.py --manifest …` — читает .srt, сопоставляет файл с фильмом каталога по manifest.
   **Анти-мусор, два уровня:**
   - *Семантика:* для RU-субтитров (OPUS-пары, `lang:"ru"`) наш RU-текст сцены (`description`+`why_fits`) матчится со строками субтитров через TF-IDF косинус с RU-стеммингом — таймкод попадает туда, где **смысл** совпадает. Для EN-файлов — keyword-группы из manifest.
   - *Консенсус:* несколько независимых файлов субтитров одного фильма (в manifest одним блоком `"file": [...]`) должны сойтись на одном моменте (±10 сек) → `consensus` растёт, `confidence = score × (1 + 0.25·(consensus−1))`, при `consensus≥2 и confidence≥порога` ставится `auto=1`.
   В `timecode_candidates` пишется только факт: `scene_id, service, timecode_label/seconds, source, source_license, evidence_sha1, line_index, match_score, confidence, consensus, auto, status='pending'`. **Текст субтитров не сохраняется** (есть тест на утечку).
2. **Авто-одобрение консенсуса:** `POST /api/admin/timecodes/bulk-approve {min_confidence, min_consensus, only_auto}` (кнопка «⚡ Одобрить все авто-консенсусные» в админке) — консенсусные кандидаты получают `verified=1` без ручного клика (`reviewed_by='auto-consensus'`). Остальное — ручная очередь: `GET /api/admin/timecodes?status=pending`, `POST /api/admin/timecodes/{id}/review {action, moment_label?}` — админ вписывает **метку НАШИМИ словами** («момент, где он извиняется»), без реплик.
3. **Выбор момента клиентом:** `GET /api/scenes/{id}/moments` — одобренные моменты сцены; в форме создания при выборе такой сцены появляются чипы ⏱ (с меткой момента), выбранный таймкод уходит в `POST /api/gifts {moments: {scene_id: label}}`.
4. **Фиксация на открытке:** при создании подарка таймкод **снапшотится** в `gift_scenes.timecode_label/timecode_seconds` — открытка фиксирована навсегда, последующие изменения каталога на неё не влияют (есть тест). Время открытия карточки (`open_at`) тоже задаётся один раз при создании.
5. В продакшене вместо sample-файлов — скачивание субтитров с opensubtitles.org по hash видеофайла (`opensubtitles`/`subliminal` на pypi) или OPUS-датасет (RU+EN пары с таймкодами); дальше те же шаги 1–4.

## Масштабирование

- OPUS OpenSubtitles v2024: ~300k+ фильмов, RU+EN субтитры с таймкодами — покрывает весь наш каталог (146 сцен) с большим запасом.
- Для новых сцен каталога: добавили фильм → прогнали сопоставление по субтитрам → очередь на ручную проверку. Импорт + ручная верификация — 1–2 минуты на сцену.
- Чтобы точнее находить «тот самый» файл субтитров (по hash видеофайла, а не по названию), в `scenes` стоит завести колонки `imdb_id`/`tmdb_id` (маппинг через IMDb datasets / TMDB API).
