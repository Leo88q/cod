# 21. Доказательный отбор таймкодов: без ручной сверки

Дата: 16.11.2026. Заменяет ручную сверку как **основной** механизм. Описывает
`app/evidence_engine.py` и `scripts/build_evidence_library.py`. Продолжает
[17-intent-taxonomy.md](17-intent-taxonomy.md) и [18-curator-workflow.md](18-curator-workflow.md).

## Зачем: почему ручной отбор был неизбежен

Прогон прежнего скоринга на реальных субтитрах (105 SRT, 62 сцены, **51 465 окон**):

| Компонент прежнего скора | Вес | Что реально давал |
|---|---|---|
| TF-IDF окна ↔ описание | 0.30 | медиана **0.004**, p90 0.023, max 0.150 — ноль |
| Лексикон категории | 0.45 | 2 общих слова («love», «time», «вместе») |
| Структура окна | 0.25 | медиана **0.90** (у 57% окон ≥0.95) |

Следствия, каждое измерено:

- порог 0.45 набирался как `0.45·(2/3) + 0.25·0.90 = 0.525` **при нулевом TF-IDF** — окно проходило, даже если по смыслу не совпадало ни с чем;
- медианный зазор между лучшим и вторым окном сцены — **0.001**, в среднем **16.9** кандидатов на сцену (до 151) — выбор был случайным;
- **18 из 62** сцен получали 0 кандидатов при наличии субтитров.

То есть оператор был не «контролем качества», а единственным фильтром. Отсюда и 0 проверенных таймкодов при 186 кандидатах.

## Что вместо этого

Таймкод — **не точка, а объект**: если два независимых издания субтитров
указывают на один и тот же фрагмент, время проверено без человека.

Три проверяемых факта вместо «магического скора»:

1. **Якорь.** Окно 25–75 сек, набравшее вес лексикона интента. Вес слова —
   редкость из корпуса (idf), а не факт совпадения: «признаюсь» весит в разы
   больше «любовь».
2. **Консенсус по содержанию.** Якорь ищется в других изданиях **не по
   секунде**, а по последовательности реплик (шинглы по 4 слова). Издания
   сдвинуты на минуты — но порядок реплик сохраняется. Совпадение ≥55%
   отпечатков = подтверждение.
3. **Достаточность.** Плотность лексикона на минуту + отсутствие негативных
   маркеров (титры, трейлер, реклама) + уверенная разметка интента.

Вердикты: `auto` — доказано, публикуется; `review` — очередь человеку;
`none` — честное «нет доказательства», сцена остаётся без таймкода.

### Почему не «±10 секунд между файлами»

Прежний `cluster_consensus` сравнивал абсолютные секунды с окном ±10 сек.
Издания одного фильма расходятся на **десятки минут** (другая нарезка,
реклама, разный FPS), поэтому консенсус почти всегда был 1 — проверено на
данных: медианный сдвиг найденного фрагмента **14 сек**, p90 — **2127 сек**.
Выравнивание по содержанию решает именно это.

### Ноль ложных совпадений

Нулевой baseline: для случайно взятого окна лучший `ratio` с другим изданием —
медиана **0.000**, доля ≥0.35 — **0%**. Распределение подтверждений
бимодальное (0.58–1.0 у настоящих), то есть сигнал не «размазан».

## Языки: подтверждение только внутри языка

Шинглы сравнимы в пределах одного языка. Поэтому:

- EN-издание подтверждается EN-изданием, RU — RU;
- лексикон тоже берётся по языку издания: EN-окно проверяется `lexicon_en`,
  RU-окно — `lexicon_ru` (прежний код давал EN-файлам RU-лексикон, который
  физически не мог сработать);
- OPUS `en.zip` + `ru.zip` — две независимые линии доказательства по одному
  фильму, и это то, что закрывает советское кино.

## Публикация ≠ проверка человеком

`scenes.verified=1` — флаг **ручной** проверки в плеере. Автоматика его не
ставит, иначе флаг перестал бы что-либо значить. Вместо этого:

| Поле | Значение |
|---|---|
| `scenes.evidence_kind` | `auto` — таймкод опубликован по доказательству |
| `scenes.evidence_editions` | сколько изданий сошлось |
| `scenes.evidence_score` | плотность лексикона + структура |
| `scenes.evidence_report` | JSON: издания, `ratio`, сдвиги (**без текста реплик**) |
| `scenes.verified` | остаётся `0` |

API отдаёт это как `published_by_evidence: true` и `evidence_editions` в
`/api/scenes/search` и `/api/scenes/semantic`; `/api/scenes/meta` —
счётчик `published_by_evidence`. Так фронтенд может честно различать
«момент подтверждён изданиями» и «момент проверен человеком».

## Запуск

```bash
# посмотреть, что будет опубликовано (ничего не пишет)
.venv/bin/python scripts/build_evidence_library.py --dry-run

# опубликовать доказанное
.venv/bin/python scripts/build_evidence_library.py --write

# строже: три издания вместо двух
.venv/bin/python scripts/build_evidence_library.py --write --min-editions 3

# вместе с локальным корпусом OPUS (см. ниже)
.venv/bin/python scripts/build_evidence_library.py --opus-dir ~/Desktop/opus-xml --write
```

Ключи: `--min-editions` (2), `--min-ratio` (0.55), `--min-intent-confidence` (0.7),
`--min-evidence` (из таксономии), `--refresh`, `--db`.

### Что важно знать про формат OPUS

- Один `<imdb>.xml` содержит **несколько `<document>`** — это разные загрузки
  субтитров одного фильма. Адаптер режет файл по документам: иначе «консенсус»
  внутри одного файла был бы фикцией.
- Текст реплики в разных версиях лежит по-разному: `<w>`-токены, `tail` у
  `<time>` или текст перед `<time>`. Первая версия `parse_opus_xml` читала
  только `<w>` и молча возвращала **0 реплик** — исправлено; формат покрыт
  тестами `tests/test_opus_adapter.py`.
- Для больших архивов есть `--limit-files` у `scripts/import_opus_timecodes.py`
  (старый путь, только кандидаты в очередь).

## Что осталось открытым

- **Юридическая проверка**: ODC-BY у OPUS не отменяет прав правообладателей на
  тексты; в БД хранятся только секунды/sha1/признаки, сам текст не сохраняется.
- Автоматическая проверка **смысла** фрагмента (NLI/эмбеддинги) сознательно не
  используется — выбрана проверяемая механика без внешних моделей. Признание
  в любви и «любовь» к пицце по-прежнему различает только контекст интента.
- `verified=1` остаётся ручным: если нужен полностью автоматический контур,
  это отдельное решение продукта (флаг уже отделён от `evidence_kind`).
- Каталог тегов (`memory_war` от слова «бо») требует вычитки: 87 сцен размечены
  правилами, 59 — вручную. Публикация гейтится `--min-intent-confidence`, но
  сама разметка — отдельная задача.
