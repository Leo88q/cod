# 17. Систематизация таймкодов: категории, типы фрагментов и gate

## Зачем это

Раньше «признание» было просто тегом-поводом: он висел на 36 сценах, включая «Матрицу», «Шрека», «Крёстного отца» и «Форрест Гамп». «Женская дружба» вообще не была категорией, а «Девчата» числились в «8 марта». SRT-скоринг сравнивал окно субтитров с общим описанием фильма, поэтому на проверку попадали любые разговоры, а 84 сцены получали детерминированный «черновик» — аккуратную, но случайную минуту.

Теперь **таймкод не имеет права появиться без категории и доказательства**.

## Две оси (как выбрано)

1. **Основной интент** — зачем дарим, один на сцену. 14 категорий ниже.
2. **Тип фрагмента** — что именно должно быть на экране: `monologue`, `dialogue`, `song_music`, `letter_voiceover`, `silent_gesture`, `toast`, `comic_gag`, `reunion`, `farewell`.

Плюс **третий слой — доказательство**: почему именно это SRT-окно подходит паре «интент + тип».

Источники истины:

- `data/timecode_library/intent_taxonomy.json` — 14 категорий, RU/EN-лексиконы, порог `0.45`, `min_lexicon_hits=2`, негативные маркеры;
- `data/timecode_library/scene_intents.json` — разметка **всех 146 сцен**: `primary_intent`, `fragment_type`, `intent_query_ru/en`, `curated_anchor`, `origin`;
- `scripts/build_scene_intents.py` — генератор разметки; **59 кураторских оверрайдов** исправляют старые расплывчатые теги, остальное — детерминированные правила по `description/why_fits/mood_tags/occasion_tags/подборкам`;
- `scripts/import_intent_candidates.py` — категорийный скоринг SRT-окон.

## Как отбирается таймкод

1. Окна SRT по 25–75 сек, начинающиеся с реплики; пропускаем первые 2 минуты и финальные титры.
2. Для каждого окна считаем:
   - совпадения с **лексиконом своей категории** (RU+EN);
   - TF-IDF косинус к `intent_query` (своя категория + описание + якорь эпизода);
   - структуру: число реплик, макс. пауза, длительность, монолог/диалог, совпадение с ожидаемым `fragment_type`;
   - негативные маркеры: титры, трейлер, `www`, «♪», реклама.
3. `score = 0.45·лексикон + 0.30·TF-IDF + 0.25·структура`.
4. **Gate**: в очередь идут только `score ≥ 0.45` **И** `≥2` лексических совпадений. Иначе сцена остаётся `needs_curator` — без времени и без кнопки «открыть на моменте».
5. Топ-3 окна на сцену с зазором ≥60 сек; консенсус ±10 сек между разными SRT-файлами.
6. В БД сохраняются только время, `sha1`, категория, тип, JSON-признаки и человекочитаемая причина. **Текст субтитров не сохраняется.**

## Что получилось в живой БД

```
сцен с SRT: 62
сцен с доказательным фрагментом: 44
кандидатов выше порога: 101
нужен куратор: 102 сцены (146 − 44)
старые 262 pending без категории: переведены в archived
verified=1: по-прежнему 0
```

Это честный gate: лучше 44 осмысленных фрагмента, чем 146 случайных минут. Для оставшихся 102 сцен в карточке есть **конкретный якорь эпизода** («финальное признание Гарри», «разговор трёх подруг», «песня лётчиков между вылетами»), а не «ищи с нуля». Куратор фиксирует эпизод → запускается SRT/OPUS-скоринг → появляется время.

Официальные полные версии Мосфильм дают `&t=<секунда>s` только там, где уже есть доказательный кандидат; пиратские зеркала и обход оплаты не используются. Для сцен без автозапуска копируется `mpv --start=<время> ...` с уже подставленной секундой.

## Команды

```bash
# пересобрать разметку 146 сцен
.venv/bin/python scripts/build_scene_intents.py

# посмотреть, что пройдёт gate, без записи
.venv/bin/python scripts/import_intent_candidates.py --dry-run

# записать категорийные кандидаты, убрать прошлый запуск, архивировать старую очередь
.venv/bin/python scripts/import_intent_candidates.py --write --refresh --archive-old

# открыть
open "http://localhost:8000/app/#/admin"
```
