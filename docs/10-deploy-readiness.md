# Подготовка к деплою: реализованный пакет и внешняя приёмка

Дата: 04.11.2026. Этот документ уточняет аудит `09`; не является заявлением «всё готово к production».

## Что добавлено в этом проходе

- Закрыто чтение чужих timeline/film/export/ICS по Telegram ID в production. Бот `/my` теперь направляет в авторизованный Mini App.
- Запрещены ответы/заметки на удалённые, просроченные и закрытые по времени подарки; исправлено оживление удалённого подарка ответом.
- Выпуск бесплатных карточек и статистика студии требуют админа в production. Отдельная ролевая модель владельцев студий ещё нужна; пока B2B обслуживает оператор с admin-токеном.
- Webhook ЮKassa больше не предполагает наличие Basic auth от провайдера. Входящий ID сопоставляется с локальным платежом; сервер делает авторизованный GET к API провайдера. Проверяются id/status/paid/amount/currency/metadata/recipient. При недоступности проверки возвращается 503. Мок-тест не заменяет боевую проверку.
- Эффект платежа применяется под `BEGIN IMMEDIATE`, статус перечитывается внутри транзакции; повторная/конкурентная доставка не выпускает повторные карточки. В production без ключей платежи отключены, dev-confirm запрещён.
- Шедулер больше не открывает второй writer для очереди; постановка напоминания и маркер обработки атомарны. Исключено напоминание о прошедшем открытии. Ошибка задачи откатывается.
- Добавлен отдельный `python -m app.worker`; локальный файловый lock не позволяет запустить два таких worker для одной БД. API отключает встроенный шедулер через `SCHEDULER_ENABLED=0`.
- Уведомления: экспоненциальный retry/backoff, после 8 ошибок `sent=-1` (dead letter). Доставка остаётся at-least-once: сбой между отправкой Telegram и фиксацией в БД может дать дубль.
- Медиа: очистка включает ответы; новые удаления/истечения отсчитываются по `inactive_at`, legacy-записи — по created_at. Непривязанные загрузки старше 48 часов удаляются. Файл, на который ещё есть ссылка, сохраняется.
- JSON request logs без query/body/headers, request ID, общий безопасный ответ 500. `/ready` проверяет доступность БД; `/api/admin/metrics` отдаёт счётчики текущего процесса и очередь, не глобальную статистику кластера.
- UI: жалоба, удаление с подтверждением, скачивание JSON своих данных, обновление медиа, список жалоб с закрытием, базовый обзор событий. Ошибки API преобразуются в пользовательские сообщения.
- Экспорт дополнен собственной активностью: replies/notes/payments/notifications/events/connections. Это ещё не утверждённый юридический реестр всех персональных данных.
- Дизайн: focus-visible, touch targets, safe-area, горизонтальная прокрутка навигации, reduced-motion, live-status. Полного WCAG/визуального аудита не было.
- Production Compose: private API + отдельный worker + Caddy TLS. Образ запускается не от root. Добавлены constraints установленных зависимостей, исправлен CI (ветки arena + реальная ошибка при изменении каталога).
- `scripts/preflight.py`, `scripts/verify_backup.py`, ограниченный локальный load-smoke.

- `node --check app/static/app.js`: успешно.

## Подготовка production-хоста

1. Установить Docker Engine + Compose. Выбрать один Linux-хост с локальным SSD: SQLite WAL нельзя переносить на NFS.
2. DNS A/AAAA домена направить на хост, открыть входящие 80/443. Не публиковать API-порт 8000 наружу.
3. Заполнить `.env`: `ALLOW_ANON=0`, `PUBLIC_DOMAIN`, `PUBLIC_URL=https://домен`, `BOT_TOKEN`, `BOT_USERNAME`, `WEBHOOK_URL=https://домен`, реальный `SUPPORT_CONTACT`.
4. Сгенерировать **разные** случайные `ADMIN_TOKEN`, `MEDIA_SIGNING_SECRET`, `WEBHOOK_SECRET` не короче 32 символов. Например `python -c 'import secrets; print(secrets.token_urlsafe(48))'`. Не помещать секреты в Git/чат/логи.
5. Настроить ЮKassa-параметры или оставить оба пустыми — тогда оплата недоступна. Реальный протокол, уведомления, чек и возврат проверить с провайдером до продажи.
6. `mkdir -p storage/media backups && sudo chown -R 10001:10001 storage`. При переносе старой БД остановить старый API/бот, сделать backup, скопировать в `storage/scena.db`; перенос медиа выполнить отдельно.
7. Установить Python-зависимости для preflight либо выполнить его в собранном контейнере. `python scripts/preflight.py` должен завершиться кодом 0. Проверка не делает сетевых запросов и не подтверждает DNS/платежи.
8. `docker compose -f docker-compose.prod.yml config` — проверить итоговую конфигурацию (вывод может содержать env, не публиковать!).
9. `docker compose -f docker-compose.prod.yml up -d --build`.
10. Проверить HTTPS, `/health`, `/ready`, авторизацию Mini App, webhook Telegram, lock/deleted подарки, загрузку/открытие медиа и тестовую оплату. Отключить старый polling-процесс при webhook-режиме.

## Эксплуатация

- API работает без scheduler; отдельный worker — один на БД. Не запускать параллельно встроенный scheduler в другом API.
- Forwarded-заголовки доверяются private ingress; закрытый порт API обязателен. Не подключать недоверенные контейнеры к этой сети.
- Caddy не раздаёт media напрямую и не включает access log с секретными ссылками. Не добавлять логирование query/body/Telegram initData в другие компоненты.
- Настроить внешний мониторинг HTTPS `/ready` и alert по JSON-записям status>=500. **Внешний сервис алертов здесь не подключён**; один `/ready` не является мониторингом.
- Проверять pending/dead-letter очередь: `SELECT sent,COUNT(*) FROM notifications GROUP BY sent;`. После устранения причины оператор может вернуть выбранные записи в sent=0, attempts=0, next_attempt_at=NULL. Не переотправлять массово без проверки.
- Backup с хоста: `DB_PATH=storage/scena.db bash scripts/backup.sh backups`; затем `python scripts/verify_backup.py backups/<файл>.db.gz`. Настроить cron и зашифрованную внешнюю копию. Скрипт хранит последние 30 файлов, не «30 дней».
- Восстановление: остановить **API и worker**, сохранить текущие DB/WAL/SHM как аварийную копию, распаковать проверенный backup в новый путь, назначить UID 10001, заменить DB и удалить только устаревшие WAL/SHM при остановленных процессах, поднять сервисы и проверить сценарии. Не заменять работающую SQLite-БД.
- Ротация media secret отзывает все подписанные URL; повторное открытие открытки создаст новые. Ротация Telegram/webhook/admin ключей требует обновления env и перезапуска/проверки webhook.

## Что ещё нельзя считать закрытым

- Удаление аккаунта/полный цикл запросов субъекта данных; сроки хранения логов/отчётов; юридические реквизиты и 152-ФЗ.
- Возвраты, чеки, бухгалтерская сверка и реальная партнёрская атрибуция.
- Полная ролевая модель студий; связь таймлайнов по взаимному согласию (сейчас добавление связи одностороннее).
- Проверка содержимого upload/нормализация изображений/антивирус; ограничение orphan storage по объёму.
- Полноценные empty/error/retry/skeleton состояния всех экранов, замена prompt/confirm на доступные формы, автообновление медиа.
- Браузерные E2E, visual regression, аудит контраста и screen reader, реальные iOS/Android Telegram.
- Полный нагрузочный профиль, SLO, внешние алерты, offsite backup, реальный production deploy.
- Полный каталог проверенных таймкодов, лицензирование каждого источника и оценка качества рекомендаций.
- Redis/горизонтальное масштабирование, CDN постеров, формальная дизайн-система, поддержка и пользовательский пилот.

Эти пункты не отмечены выполненными только ради «зелёного» чек-листа.
