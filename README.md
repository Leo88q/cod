# 🎬 Сцена

Как работает услуга end-to-end и полный инвентарь фичей — `docs/07-service-flow.md`. Таймкоды — всегда **отрезки** (начало–конец, 25–75 сек), фиксируются снапшотом в открытке; источники и пайплайн — `docs/06-timecode-sources.md`. Аудит «что ещё не продакшн» и что закрыто — `docs/08-prod-gaps.md` (аналитика `GET /api/admin/analytics`, экспорт данных `GET /api/users/{tg}/export`, напоминание `gift_soon`, очистка медиа, онбординг бота, ступенчатый rate limit) (ЮKassa-webhook auth, лимит загрузок, CORS, fail-safe анонима, жалобы/удаление подарков, /privacy + /terms + чекбокс 152-ФЗ, WAL + `scripts/backup.sh`, CI, docker-compose).

Приложение «общий фильм» для двоих и семьи: даришь повод (букет) + **сцену из фильма с таймкодом** и личным сообщением — получатель отвечает своей сценой, и из сцен складывается ваш общий таймлайн.

Монетизация: QR-карточки в букеты для цветочных студий (B2B), комиссия 10–15% с заказов букетов через прямые ссылки магазинов на Flowwow (zero-commission для магазина), премиум «ваш фильм».

Библиотека таймкодов, автономная (подробнее — `docs/06-timecode-sources.md`): `scripts/fetch_timecodes.py` извлекает кандидатов из субтитров OpenSubtitles/OPUS семантически (RU: TF-IDF по смыслу нашего описания; EN: keyword-группы) + **консенсус** нескольких версий субтитров (±10 сек) → `timecode_candidates` с `confidence/consensus/auto` (только факт таймкода + sha1 + source/license, без текста реплик). **Авто-одобрение отключено по умолчанию**: `verified=1` ставится только вручную через `POST /api/admin/timecodes/{id}/review` с обязательным `version_note`; `POST /api/admin/timecodes/bulk-approve` доступен лишь при явном `ALLOW_BULK_AUTO_APPROVE=1`. Очередь: `GET /api/admin/timecodes`, метка момента — нашими словами. Клиент выбирает момент: `GET /api/scenes/{id}/moments` + чипы ⏱ в форме создания (`moments` в `POST /api/gifts`); таймкод **фиксируется снапшотом** в `gift_scenes` — открытка неизменна навсегда, `open_at` тоже задаётся один раз.

Каталог сцен как «система находок» (`#/catalog`): `GET /api/scenes/meta` отдаёт категории с подсчётами (поводы, настроения, жанры, эпохи, возраст, всего/проверено); фильтры — повод, настроение, жанр, эпоха, возраст, «✓ только проверенные», «⏱ с таймкодом», «⭐ закладки», сортировка (популярность/год/название), чипы подборок; текстовый запрос — семантический `POST /api/scenes/semantic`; состояние фильтров — в hash URL (шарable ссылка). `POST /api/scenes/search` принимает `genre/era/age/verified_only/has_timecode/sort`.

## Ручная сверка таймкодов и библиотека источников

Большой каталог (146 сцен) исторически был без реальных таймкодов: сиды содержали заглушки `"0:00:00"`, а SRT-образцы не коммитились. Теперь есть повторяемый мост к внешним библиотекам:

```bash
.venv/bin/python scripts/import_timecode_library.py   # полный манифест: 62 сцены / 105 SRT+CSV / 4 зеркала
.venv/bin/python scripts/import_timecode_library.py --pilot   # 20 кураторских сцен / 38 SRT
bash scripts/dev.sh                                    # затем #/admin с ADMIN_TOKEN
```

Импортёр сначала берёт файлы с `raw.githubusercontent.com` — это **не расходует лимит GitHub REST API**; если raw-хост закрыт, уходит в `api.github.com`. При повторном `HTTP 403 rate limit exceeded` задай `GITHUB_TOKEN`/`GH_TOKEN` в терминале (например `export GITHUB_TOKEN=$(gh auth token)`), токен в чат не передавай.

`source_registry.json` + `srt_index.json` описывают 4 GitHub-зеркала (39 861 + 1 300 + 14 SRT и 1 305 CSV), `imdb_map_full.json` даёт 133 IMDb ID на 140 сцен каталога. Для OPUS / OpenSubtitles v2024 на локальной машине есть `scripts/import_opus_timecodes.py`. Сводка покрытия — `GET /api/admin/timecode-library` и панель «📚 Библиотека таймкодов» в админке.

Инструкция оператора: [docs/13-timecode-verification.md](docs/13-timecode-verification.md), масштабирование/источники: [docs/14-timecode-library-scale.md](docs/14-timecode-library-scale.md), легальные deep links: [docs/15-moderation-links.md](docs/15-moderation-links.md), **служебная очередь на все 146 сцен** (свёрнута в админке): [docs/16-moderation-board.md](docs/16-moderation-board.md), **систематизация по 14 категориям**: [docs/17-intent-taxonomy.md](docs/17-intent-taxonomy.md), **как куратору отбирать**: [docs/18-curator-workflow.md](docs/18-curator-workflow.md), **первый блок «признание в любви и чувства» на 50 фильмов**: [docs/20-love-confession-batch.md](docs/20-love-confession-batch.md). Админка показывает одну компактную таблицу на 50 строк: фильм, редактируемая прямая ссылка VK/Rutube, начало, конец, версия издания и проверка. У 9 фильмов ссылка на точную официальную полную версию уже подставлена, у остальных 41 поле пустое — поисковые URL и чужие «Мосфильм»-ссылки не подставляются. ## Доказательный отбор таймкодов (16.11.2026)

Ручная сверка больше не единственный путь: момент публикуется, если его
подтверждают **независимые издания субтитров** (выравнивание по содержанию, а не
по секундам). Прежний TF-IDF-скоринг на окнах 25–75 сек давал медианный вес
**0.004** — порог набирался двумя общими словами и «нормальной длиной окна»,
поэтому 17 кандидатов на сцену выбирались случайно.

- `app/evidence_engine.py` — якорь по интенту (idf вместо «факта совпадения»),
  консенсус изданий по шинглам, gate по плотности и негативным маркерам;
- `scripts/build_evidence_library.py` — сборка и публикация (`--dry-run` / `--write`),
  `--opus-dir` для локального корпуса OPUS v2024 (RU+EN);
- `scenes.evidence_kind='auto'` — таймкод опубликован по доказательству,
  `scenes.verified` остаётся флагом **ручной** проверки и автоматикой не ставится;
- API: `published_by_evidence` и `evidence_editions` в поиске/семантике,
  `published_by_evidence` в `/api/scenes/meta`.

Результат на GitHub-корпусе: **11 сцен опубликованы без человека** (было 0),
39 — в очередь, 8 — без доказательства. Подробно: [docs/21-evidence-engine.md](docs/21-evidence-engine.md).

## «Ваше кино»: продукт без чужих фильмов (16.11.2026)

Кинотека тянет права, издания, таймкоды и проблему «включить негде» (из 11
доказанных сцен ссылку на плеер имеет 0). Поэтому появился путь без фильмов вообще:
вертикальный фильм из **своих** фото и голоса.

- `scripts/make_film.py` — рендер MP4 1080×1920: кадры 9:16, подписи, градиент,
  прогресс-полоски, кириллица; кадры подстраиваются под длину голоса;
- `POST /api/film/build` — фото из `/api/upload` + голос → подписанная ссылка
  `/media/film_*.mp4`; чужие пути и `../` отклоняются, 2 сборки на процесс;
- 12 тестов, включая проверку, что на выходе валидный MP4 1080×1920 с аудио.

Сборка 3 фото + голос — **2.7 сек**, 313 КБ. Варианты и минусы:
[docs/22-product-without-films.md](docs/22-product-without-films.md).
Кадр прототипа: `docs/assets/your-film-frames.png`.

## Гениальное простое: одна фраза на точное время (16.11.2026)

Продолжение идеи «что заменяет видео». Опирается на то, что уже есть в коде:
`open_at`, `series_days`, `locked_count`, `replies` с фото и голосом.

**«Одна фраза»**: подарок — одно предложение, назначенное на точную минуту
(«в 21:40 скажи ей это»). Создание — 20 секунд, кинотеки нет, лицензий нет.
До времени не видно, после — остаётся только факт «14 февраля, 21:40».
Получатель отвечает фразой, через год дарит уже он, в ту же минуту; семь лет —
видимая шкала из семи строк.

Почему выигрывает у «Премьеры»: создаётся за 20 секунд вместо 5 минут и живёт
годами вместо одного вечера. Разбор, четыре уточнения (второй пишет в любом
мессенджере, тишина до открытия, только факт после, пропущенная минута — не
наказание) и проверка за один вечер:
[docs/26-one-sentence.md](docs/26-one-sentence.md).

## Что заменяет видео и что удивляет (16.11.2026)

Видео не удивляет, потому что стало дешёвым — человек собирает слайд-шоу в
телефоне за 20 секунд. Удивляет не формат, а **ограничение**. Пять рычагов,
и все уже есть в схеме:

| Рычаг | Поле |
|---|---|
| церемония времени | `gifts.open_at`, `series_days` |
| необратимость | `expires_at`, статусы |
| невоспроизводимое усилие | форма дарителя |
| соавторство с получателем | `replies` (фото, голос) |
| находка в реальном мире | `cards`, `shops`, QR |

Рекомендация: **«Премьера» + «один раз» + титры** — одна минута на двоих,
подарок сгорает, потом получатель дописывает свой кадр. Без кинотеки и без
обязательного видео. Разбор, риски (часовые пояса, «второй не пришёл») и что
перестать делать: [docs/25-what-replaces-video.md](docs/25-what-replaces-video.md).

## Таймкоды: источник — видео с правами, а не субтитры (16.11.2026)

Легально масштабировать субтитры нельзя, а текущая схема даёт **0 из 11**
легально показываемых сцен. Решение: **заменить источник, а не отказаться от
таймкода**.

- `scripts/detect_cuts.py` — монтажные склейки прямо по картинке (64×36 RGB,
  10 к/с, numpy, без нейросетей и внешних API). Порог относительный: пик в
  8 раз выше медианы окрестности (в статике медиана и MAD равны нулю, любой
  абсолютный порог ломается). Проверено: границы 3 с и 6 с найдены как 3.2 и
  6.2; статичный кадр, один кадр и битый файл — 0 ложных склеек.
- Субтитры не нужны ни для границ сцен, ни для эмоций: правило «не хранить
  текст» становится тривиальным.
- Правка продукта: сцена = **интервал (начало, конец)**, а не мгновение.

Обоснование, варианты и что делать с 61 сценой на субтитрах:
[docs/24-timecodes-replacement.md](docs/24-timecodes-replacement.md).

## Площадки: Telegram + VK + Одноклассники (16.11.2026)

Одно Mini App работает в трёх мессенджерах. Регистрация в VK Mini Apps
автоматически даёт витрину ОК (создание приложений внутри ОК больше не
поддерживается), поэтому вторая соцсеть — бесплатно.

- `app/platform_auth.py` — проверка подписи запуска VK на бэкенде
  (base64url HMAC-SHA256; подменить `vk_user_id` нельзя — покрыто тестами),
  единая идентичность `user_identities(provider, external_id) → users.id`,
  Telegram-совместимость (`users.telegram_id`) сохранена;
- `POST /api/auth/vk`, `GET /api/platform`;
- `app/static/platform.js` — мост для трёх платформ, нативная история VK
  (`VKWebAppShowStoryBox`) под ролик «ваше кино»;
- MAX: технически похож на Telegram, но публиковать ботов и Mini Apps могут
  только верифицированные юрлица РФ — не для MVP.

Что брать с GitHub (и что не брать), лицензии и ограничения площадок:
[docs/23-platforms-and-github.md](docs/23-platforms-and-github.md).
